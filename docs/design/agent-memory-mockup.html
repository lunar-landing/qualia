长期记忆 · 产品设计

对话中可存 · 回答时可用 · 面板里可管

这个功能解决什么

产品定位

现在的智能体每次对话都是白纸：项目用构建命令、你的环境习惯、沟通偏好，换个会话就要重讲一遍。 长期记忆让智能体把这些「值得记住的事」存下来，跨会话生效。

记得住
对话里说「记住…」，智能体归类保存（角色 / 事实 / 偏好）；内容、类型、时间可追溯。
看得见
保存与引用都有明示——回答「基于 1 条记忆」有标注，不黑箱。
管得了
侧边栏「记忆」面板：逐条删除、随时清空、总开关一键停用。
一句话：智能体的「用户手册」——它自己记录、自己查阅，用户随时可审查修订。对标 ChatGPT Memory 与 Claude 的 memory 能力，但条目完全本地存储、用户全权可控。

记忆的组织形态

不必一条条平铺

记忆推荐按类型分区组织——三类记忆的写入门槛、注入优先级、管理方式本就不同： 角色定位（我是谁、智能体该扮演什么，仅显式设定）、 事实记忆（项目与环境等客观事实，对话中确认后写入）、 偏好记忆（沟通与工作方式倾向，V2 起可自动沉淀）。 「知识图谱」形态评估后暂不做，理由见 C 卡。

平铺列表 FLAT
＋ 实现最简，无归类出错环节
－ 条目过 30 条后难扫读；注入无优先级，管理粒度粗
结论 仅适合记忆量极小的早期，直接跳过
推荐
分类分区 TYPED
角色定位 1
事实记忆 3
偏好记忆 2
＋ 三类各有治理规则：角色定位仅显式设定、事实需确认、偏好可自动沉淀
＋ 注入可按类定优先级与 token 预算；面板管理清晰
－ 写入时多一步归类（智能体自动判断，归错可手动删改兜底）
结论 MVP 采用
知识图谱 GRAPH
＋ 支持实体关系推理与多跳检索（如「A 负责的项目的构建命令」）
－ 每条记忆需额外实体/关系抽取调用；冲突消解与图谱维护复杂
－ 普通用户读不懂图——与「用户可审查」的产品原则冲突
结论 远期探索：记忆过百且出现多实体关系需求后再评估

交互规则

写入 / 不写入 / 边界

什么会进记忆

场景行为
明确指令写入「记住…」「以后都…」「我的习惯是…」→ 自动归类保存并在回执中标注类型
记忆类型三类分区：角色定位（仅显式设定）/ 事实记忆（对话确认后写入）/ 偏好记忆（V2 起支持自动沉淀提议）
更正既有记忆更新命中已有条目时原位更新，不重复追加
模糊的顺口一提不写入「今天好累」这类一次性闲聊、代码片段、临时结论不入库；拿不准时询问用户「需要记住吗」
敏感信息不写入密码、密钥、token 类内容拒绝保存（提示词硬约束）
记忆使用边界仅作参考上下文；与当前指令冲突时当前指令优先；只读模式下只读不写
上限总数 200 条软上限 + 分类软上限（防单一类型挤占），接近时智能体在回执中提示整理（合并/清理旧条目）

版本范围

MVP 先行
MVP 首版
  • 对话内显式记住 / 更新 / 忘掉（工具 + 回执标签，含类型标注）
  • 三类分区组织：角色定位 / 事实记忆 / 偏好记忆，面板分节管理
  • 记忆全量注入每次对话（自动生效）
  • 回答「基于长期记忆」小字标注
  • 侧边栏记忆面板：列表 / 逐条删除 / 清空 / 总开关 / 空态
  • 敏感信息拒存 + 200 条软上限
后续演进 V2+
  • 自动反思：会话结束时智能体提议「这条偏好要不要存入记忆」（偏好类为主要来源）
  • V3 探索：知识图谱（实体-关系抽取），记忆规模与关系型需求出现后再评估
  • 记忆检索：条目变多后按需检索而非全量注入
  • 面板编辑：条目内容直接修订（MVP 只支持删除）
  • 来源追溯：面板中展示每条记忆来自哪个会话
