01设计目标与约束

状态常显当前模式一眼可见，不能只靠记忆或悬停提示——只读模式误发写指令的代价是心智负担
一步直达两态场景下切换应为单击；不引入「循环切换」的绕路（Shift+Tab 心智是终端用户专属）
低空间成本工具行已有附件、模型选择、发送三组控件，模式控件需要克制，不与主操作（发送）抢视觉
可扩展二期若引入第三种模式（如「自动」按需执行），控件结构不需要推翻重来

04推荐与落地样式

最终决策：采用方案 B（模式按钮 + 上拉菜单）；着色规则：当前选中恒为主题强调色（黑/白，不用蓝），未选中恒灰。原推荐 A 供追溯：
  • 选中态语义（按最终决策修订）：当前选中恒为主题强调色（--accent，日间近黑/夜间近白，与发送按钮同体系），不区分具体模式；未选中恒灰（hover 仅底色反馈，不提亮文字）。
  • 输入卡状态描边（全局反馈）：问答态给整个输入卡加强调色描边 + 光晕，模式状态在控件之外二次外显，视线扫到输入区即可确认。上方各方案 mock 已演示此效果。
  • 键盘补充（吸收 D 的优点）：注册 Ctrl+Shift+M 循环切换，状态与分段控件同步；tooltip 标注快捷键。不做唯一入口。
  • 二期衔接：若引入「自动」等第三模式，分段控件扩为三段；闭环按钮（问答态答毕后「切换到智能体模式执行」）沿用同一强调色，色彩语义一致。
决策修订：原推荐 A，经审查采纳 B（菜单内建说明的引导价值 > 两步操作成本）；若评估变化可复评 A。
