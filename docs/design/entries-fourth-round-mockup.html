欢迎页收纳 · 入口做成新会话 Hero 卡组

低频入口的共同困境：常驻占位，但打开时点随机。M 案把两者从侧栏拆除， 做成欢迎页（新会话 Hero）的能力卡组——与已有的模型/MCP/技能状态卡同族。 每张卡带实时状态（任务数/最近运行、库文章数/最近更新），点击进现有整栏视图。 欢迎页是每次新会话必看之处，可发现性反而高于侧栏角落；长期会话用户则走 / 命令兜底。

N

情境化触达 · 取消中心页，功能以卡片活在消息流

理念最激进的一案：「中心页」是 web 思维遗留，agent 产品里一切都该是对话的上下文。 新建/编辑任务由对话完成（agent 调用 schedule 工具，产出一张任务卡片钉在消息流，启停就地操作）； 资料引用时 assistant 尾部出引用芯片，点击升阅读层；「任务中心」降级为设置里的一个列表页。 入口问题不复存在——功能即内容。

侧栏页签化 · 「会话 | 功能」同宽双 Tab

推荐
承认一个事实：低频入口的展开概率低，但发现概率需要常驻——那就别压成图标、也别藏进浮层， 而是给侧栏加一层页签：品牌行下 会话 | 功能 双 Tab（同宽、互斥、状态保持）， 「功能」页内是文字行导航列表（定时任务 / 资料中心 / 未来技能…），点击照旧开整栏。 顶部两行 → 一个 Tab 字符，可发现性保留（文字常驻可见）而成本降到 ~30px。

P

工作区面板宿主 · 入口借右面板的 Tab 语言

入口搬出侧栏，挂到工作区面板（已占右缘 1/3 视口）的 Tab 族：文件 | 任务 | 资料。 语义自洽——工作区面板管「这个项目的上下文」，任务与资料正是两类项目上下文； 且聊天永远不被整栏替换：面板内的任务清单可就地启停，「打开完整视图」按钮才升整栏。 侧栏顶部两行删除，回归纯会话。

对比与结论 · 四轮总收敛

方案维度侧栏成本可发现性打断聊天改动量主要代价
M · 欢迎页收纳 时机0 行 新会话强 / 老会话弱整栏（不变）Hero 卡组 + 命令兜底 长会话中入口不在场，依赖 / 命令面板
N · 情境化触达 时机0 行 无主动门（靠 agent）彻底不打断产品理念级 资料的主动浏览场景无法被芯片替代
O · 侧栏页签化推荐 宿主~30px 一个 Tab 条 文字常驻可见整栏（不变）侧栏内加 Tab 功能访问 1 击 → 2 击
P · 右面板宿主 宿主0 行 随面板开合面板态不打断面板加 Tab + 全局/项目语义题 面板收起即无入口；全局功能装进项目容器的语义争议

四轮横评后的第一梯队

O（页签化）与 I（工作台 Hub）是仅有的两个「可发现性不降、成本确实减半」的方案； 且正交可叠加：O 的「功能」Tab 内只放一行「工作台」→ I 的 Hub 页， 给未来技能/MCP/记忆全部留好插槽——这是十一个方案里唯一同时回答「现在」与「两年后」的组合。

N 是理念奖，不是交互方案

「任务即对话」方向正确但资料无法跟进（主动浏览无锚点），且砍掉任务中心页动的是产品骨架。 建议拆一小步落地：新建任务支持对话式创建（agent 工具直接产出任务），中心页保留——先收 N 的红利，不付 N 的代价。

别再动的方向

rail（C）结构成本无回报、app bar（E）毁终端沉浸、品牌下拉（L）压死中频功能、 虚拟行（H）区分度调不平——四轮验证这几条属于已排除坐标，后续设计不必再回旋。
