对比与结论

方案入口形态展示形态侧栏纵向成本打断聊天改动量主要代价
A · 现状 顶部双行常驻主区整栏 两行黄金位整栏替换— 低频功能常驻顶部；打开即离开会话
B · 图标化收编推荐 header 两枚图标主区整栏（不变） 零行整栏替换仅入口层 图标语义靠 tooltip；可发现性略降
C · 左缘 Rail 46px 导航条左栏内容切换 零行（代价是 46px 横向）不打断结构级 198px 左栏偏窄；任务卡片、资料阅读受限
D · 差异化 资料保留入口 / 任务进 header整栏 + 右抽屉并存 一行任务不打断新增抽屉组件 两种展示规则并存，一致性弱

推荐 B · 秩序优先

次级视图保持「图标入口 → 整栏视图」单一路径，机制零新增；侧栏顶部回归纯会话。 代价仅是入口缩为图标，配 tooltip 与展开态圆点即可兜住。改动集中在 SidebarArea 一处。

C 的适用边界

当全局入口继续增多（记忆 / 技能 / 图谱…），header 钮组放不下时，rail 是自然演进方向。 届时 C 替换的是整条侧栏导航，而不仅是这两个入口——现在不必预支这份结构成本。

D 的适用边界

若「边聊边盯任务执行」成为高频诉求（如巡检类任务的即时反馈），再把任务降为抽屉。 抽屉语言可复用工作区面板（宽 360px、右缘贴靠、不遮聊天），实现成本可控。
