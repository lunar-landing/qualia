方案对比与结论

维度V1 迷你统计条V2 统计卡（推荐）
信息密度总量 + 矩阵，hover 才见明细，指标需进详情总量/日均/峰值/活跃 + 矩阵一屏可读，详情弹窗只承担趋势图
视觉重量≈ 一行工具条，Hero 几乎零侵入一张低饱和卡片，置于输入框下方（次要位），不抢焦点
焦点风险无存在轻微卡片存在感 —— 通过灰阶配色、无彩色装饰、14px 圆角弱化
实现成本纯 CSS + 复用现有 /stats/tokens 接口与详情弹窗，无后端改动同左；仅卡片容器与指标行多约 30 行样式
结论：推荐 V2。理由：① Hero 目前内容过疏（logo + 两行字），统计卡补足视觉重量而不添操作负担；② 「新建会话」与「上期用量回顾」场景自然衔接，触达率高于侧边栏底部死角；③ 侧边栏由此回归纯导航，消除唯一的异类数据展示块。落地注记：qualia-code-ui 将 TokenHeatmap.vue 的矩阵渲染抽为可复用子块挂入 WelcomeHero，侧栏原位移除；qualia-claw 将 token-map.js 拆「矩阵渲染 / 详情弹窗」两段供 Hero 容器复用，accent 与热力阶梯随各自主题变量。会话中查看统计属低频需求，暂不补顶栏入口，保持改动最小。
