  • 左右两栏失去同高分隔线，现有「严格同线」的横向节奏被打散

诊断
  • 左栏 --mat-card #fff 与右栏 --mat-surface-2 #f7f9fb 仅差 8 个 RGB 单位（夜间 #0d1117 vs #11161e 差 4），底色其实已经“差等于没有”
  • 割裂感主要来自那 1px border-right，不是颜色
  • 右头部本来就是白底压在灰底上，左头部却是白底压在白底上——两个头部同高却不同构
F1 / F2 的完整改动（三行 CSS）
  • .kb-tree-col { background: var(--mat-surface-2) } 从 card 换过来，两栏 body 同色
  • .tree-head { background: var(--mat-card) } 补上，保住横贯页面的白色头带
  • F2 再加一行：border-right-color: rgba(28,33,40,.045)（或直接 none）
连带要改的一处
  • .filter-row 下沿用 --border-color #d0d7de，比 --mat-line 重两档；两栏同底后它会变成左栏最扎眼的线，建议换 --mat-line
  • 树行 hover --mat-wash #f2f5f8 比新底 #f7f9fb 更深一档，选中态 accent wash 也仍然可见，不用动
风险点
  • 左栏失去白卡底后，“树 = 独立面板”的心智靠头部白带与竖线残留支撑；F2 完全无竖线时只能靠 8px 内边距与字号层级
  • 正文区的 .src-code / .doc-card 是白底，在灰底上反而比现在更浮起——这是好事，但得确认不与卡片描边叠加过重
建议
  • 选 F2：比 F1 就多改一行，融合感差别最大；比 F3 便宜得多，且不推翻现有“左右头部严格同线”的节奏
  • F3 不融合而是同构：把反差拉开到 #eef1f5 才真看得出分层，代价是得给两栏包卡（圆角 + 描边 + 10px 缝），与列表页一致但页面重一档
  • F1/F2 与前面任何一版骨架（V2/V3/V4）都不冲突，可先单独上背景再讨论头部

推荐与落地拆法（V2）

  1. 新增通栏 kb-page-head，56px，background: var(--mat-card) + 下沿 var(--mat-line)：返回箭头 → kv-tile 同款 26px tile → 库名 15.5px/650 → 描述单行省略 → 三枚 kv-chip（篇数 / 字数 / 更新时间）→ spring → 上传、新建文件夹、新建文章 ghost 钮 → 竖线 → 编辑库、删除库图标钮。
  2. tree-head 由 49px 降到 38px，文案换 目录 + 计数 chip，右侧只留「全部展开 / 刷新」；三枚创建钮与上传钮全部上移通栏，长库名不再截断。
  3. reader-head 同步降到 38px，保持左右分隔线同线；去掉 back-btn，面包屑从目录段起写（不再重复库名）；视图切换 view-switch 沿用现规格不动。
  4. 删除 kb-hero 整块及其 .mark / .t / .desc / .meta 样式；目录首页直接以 gt 分组头开篇。
  5. 三态动作归位：通栏只放库级动作且恒定；阅读态与编辑态的取消/保存仍留在 reader-head，不混进通栏。
  6. 若嫌新增一层头部偏重，退一档选 V3：不动栏结构，仅把 kb-tree-col 顶部换成库信息块并删 kb-hero，问题同样能解掉七成。
