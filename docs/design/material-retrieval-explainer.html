资料库检索逻辑 · 交互讲解

导航式三层检索 + 关键词全文兜底 —— 下方的检索模拟器与后端 Java 实现（MaterialService.search）逐行同逻辑

非 RAG 不切块 现场扫描 · 无持久索引 零外部依赖 topK = 8

01三层检索体系：每层回答一个不同的问题

四个读侧工具构成流水线，决策者是模型本身（由工具 description 与系统提示词编排），每轮按需串行调用，终点汇合到 material_read。

material_list

入口

有哪些库？

列出全部资料库（名称/描述/文章数/总字数）。库发现的唯一入口，系统提示词不注入库清单快照，增删即时生效。

material_tree

导航层

库里有什么？（面）

全量目录树：文件夹 + 每篇的标题、字数、首行摘要与相对路径。模型靠树与摘要建立全局结构认知。

输出上限 200 行 · 超限截断并提示转 search
material_search

召回层

目标在哪里？（点）

正文全文关键词检索，IDF 加权排序，返回 top 8 命中文章的片段与路径。tree 失效时的兜底。

现场扫描 · 无持久索引
material_read

精读层

内容是什么？（事实源）

整篇返回 frontmatter 元信息 + 全文 Markdown，不切块。所有路径的汇合点，唯一的答案来源。

50,000 字符截断保护
铁律：search 的片段仅用于「确认相关性、拿到 path」，回答引用必须先 material_read 阅读原文 —— 片段可能断章取义，原文才是唯一事实来源。该规则同时写入工具描述与系统提示词。

02三条典型检索路径

点击场景切换。虚线节点是触发条件，红色节点表示该工具止步（fail → 换路），深色节点是本轮的实际执行者。

场景：库内几十篇文章，目录树一次全览（≤ 200 行）。
material_list→ material_tree→ material_read→ 回答（注明来源 path）
search 不出场。模型扫一眼标题 + 摘要即可锁定目标，行为与没有 search 的版本完全一致 —— 小库体验零变化。
场景：数百篇文章，目录树超过 200 行被截断。
material_list→ material_tree 输出截断：仅前 200 行 + 提示改用 search→ material_search(关键词)→ material_read→ 回答
截断提示起「导航牌」作用：模型明确知道树没看全，转用 search 按用户问题中的关键词补齐定位，而不会基于半棵树瞎猜。这同时堵住了目录全量渲染挤爆上下文的问题。
场景：目标概念只出现在正文中（如「回滚」二字没出现在任何标题/摘要里）。
material_list→ material_tree 元数据无命中 → 导航失效→ material_search("回滚")→ material_read→ 回答
tree 的召回上限 = 元数据覆盖率：标题和首行摘要没写的概念，导航永远找不到。正文级定位只有 search 能做 —— 这是不做 RAG 的前提下补齐召回率的关键一层。

03material_search 原理 · 可运行模拟

模拟库含 6 篇文章。修改查询词，下方五步实时重算，与 Java 实现完全同逻辑。

1

分词 · extractTerms

ASCII 连续串作为整词（lint）；中文连续串拆 2-gram（相邻两字一组，如「回滚方案」→ 回滚 / 滚方 / 方案）；去重保序。不用词典就能让「如何部署」和文章里的「部署」对上；无意义组合（滚方）交给下一步 IDF 自动压权。
2

现场扫描 · 一遍遍历

Files.walk 遍历 articles/ 全部 .md，逐篇剥 frontmatter，统计三个信号：哪些词命中标题、哪些词命中路径、每个词在正文出现几次（TF）。此刻不缓存任何正文 —— 内存里只有统计数字。
信号 = { titleTerms: Set, pathTerms: Set, bodyTf: Map<词, 次数> }
3

IDF 评分 · 越稀有的词越值钱

df = 包含该词的命中文档数。「的」「服务」几乎每篇都有 → IDF≈0，加不加分无所谓；「回滚」只有 3 篇有 → IDF 高，命中即强信号。这套朴素加权是 BM25 的简化版。
IDF = ln( 1 + N / (1 + df) )　·　N = 命中文档数
4

加权求和 · 排序取 top 8

标题命中比正文顺带一提更可信（3 倍权重），路径次之；正文按词频带饱和（ln TF，出现 10 次不会是 1 次的 10 倍）。
得分 = Σ [ 标题 3×IDF + 路径 1.5×IDF + 正文 (1 + ln TF)×IDF ]
文章标题命中路径命中正文 TF得分
5

片段提取 · 惰性回读

此刻才回读 top 8 的正文（此前全文从未进过内存），找最早命中位置，取「前 30 字 + 后 120 字」窗口；正文无命中的（纯标题命中）回退首段摘要。片段只用来确认相关性 —— 回答必须 material_read 原文。

04设计取舍与边界

取舍为什么不切块、不建索引

本地 wiki 定位是通读理解而非片段拼凑；库规模（几十~几百篇）下现场扫描是毫秒级；零索引 = 零维护、零一致性问题，上传即生效。规模过千再谈持久索引。

取舍为什么用 2-gram 而不是分词词典

整词匹配需要词典（jieba 等）引依赖；单字区分度太差。2-gram 零词典即可跨词边界命中，噪声 gram 被 IDF 自动压权 —— 用统计代价换工程简单。

取舍标题为什么 3 倍权重

标题是作者对全文的浓缩承诺，标题命中比正文偶然提及可信度高一个量级；路径次之（目录命名也是人工组织信号）。比例 3 : 1.5 : 1。

边界字面匹配的天花板

搜「回滚」找不到只写「撤销上线」的文章 —— 同义改写是关键词检索的结构性盲区。升级路径：接入向量（DashscopeEmbeddingModel 已就绪）做 RRF 融合，导航层与精读层完全不动。
