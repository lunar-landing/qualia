资料树文件图标 · 颜色区分

264px 文章树栏 · 与聊天附件 / 上传预览条的既有配色对齐

现状树图标字形已按类型区分但颜色统一灰阶；而聊天附件 chip 与上传预览条已在用 .icon-pdf / .icon-word 彩色词汇。 本稿对比三个取态，已定稿 C · 全类型上色（md/html 色值见下方调色板）。右上角可切换夜间验证两主题可读性。

A · 灰阶现状 树最安静，词汇断裂
设计点
  • 现状即如此：色彩随 --text-secondary，代码注释注明「克制」是刻意决策
  • 优点：树是导航区，全灰阶最安静，与石墨 + 唯一 accent 语言完全一致
  • 代价 1：同一份 PDF 在聊天 chip 是红色、进树变灰 —— 词汇断裂
  • 代价 2：12px 下字形差异弱，类型辨识要逐行读文件名后缀
B · 仅原件上色 pdf 红 / docx 蓝，md 保持灰阶
设计点
  • 判据 =「二进制原件」：pdf 红、docx 蓝（未来 excel 绿）——与既有 .icon-* 逐一对应，零新增颜色
  • md 是库内多数派 = 默认态，保持灰阶；少数原件行自然跳出，颜色是信息不是装饰
  • 颜色是前注意（pre-attentive）特征，扫视定位「那几个 PDF」明显更快
  • html 归入文本灰阶 —— 与 docIconMeta 现状一致（html → icon-text）
  • 文件夹图标不参与：结构 ≠ 内容类型
C · 全类型上色定稿 md/html 也上色，辨识最彻底
设计点
  • md 蓝 / html 橙一并着色，任何行不看后缀即可辨类型
  • 但 md 占多数时彩色行过半，颜色从「信息」退化为「装饰」，扫视收益反而下降
  • md/html 无既有词汇背书，需新增 2 个色值并解释「为什么是这个色」
  • 整树彩色化与石墨灰阶 + 唯一 accent 的克制语言冲突，选中态竖条被稀释
词汇一致性对照 —— 同一份「发布流程.pdf」的三处上下文
颜色不该在上下文之间漂移；现状断在「聊天 → 树」这一步。
