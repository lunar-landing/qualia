多栏问答窗口

可行性与设计 —— 同时并排查看多个会话 · 流式互不干扰 · 后端 0 改动

01可行性结论

结论：能支持，且后端 0 改动。这是现有架构"无 currentSessionId 判断"重构（流事件只写 store、后台会话并行流天然支持）的直接红利——多栏只是把已经并行的数据流，从"切换呈现"升级为"并排呈现"。
消息/流状态按 sid 存取chat.messagesOf(sid) / chat.streamOf(sid)，多会话消息已在同一 store 内并行维护
流连接按 sid 管理connections: Map<sid, StreamConnection>；流事件处理无 currentSessionId 判断，后台流天然支持
后端单实例多会话并行ReActAgent 请求级参数贯穿（detectedLanguage / readOnly 先例），每栏独立提问互不污染
唯一的全局耦合是"呈现层"ChatArea/InputArea 读取 sessionStore.currentSessionId 单值——多栏改造就集中在这两处参数化

布局规则：主栏（第 1 栏）常驻，最多 3 栏；栏间 1px 分隔线，活动栏顶部 2px 强调色条；每栏独立输入区、独立滚动跟随、独立流状态。宽 ≥1600px 允许 3 栏，1200-1600px 允许 2 栏，<1200px 自动收拢为单栏 + 栏标签（见 06）。

03交互设计

打开分栏会话列表项 hover 出现 ⧉ 按钮（或右键菜单「在分栏中打开」）；点击后右移新栏并聚焦，原主栏内容保持不动
去重同一会话不允许在两栏同时打开——已在某栏时，再次打开操作改为聚焦该栏
关闭分栏栏头 ✕ 关闭；正在流式的栏关闭需二次确认（流继续在后端跑，与"停止生成仅断开前端"语义一致）
聚焦点击任意栏即为聚焦栏；聚焦栏承接新建会话、侧栏普通点击切换等"默认目标"行为
未读提示非聚焦栏收到新 step/answer 时，栏头出现小圆点/计数；流结束转为常驻提示，点击栏即清除
删除联动删除已在某栏打开的会话：该栏自动关闭；主栏会话被删除回到欢迎态（现有行为不变）
栏内消息全部复用现有 MessageItem/工具 chips 渲染；文件预览层保持全局覆盖（v1 不分栏预览）。

04状态与数据流（代码示意）

// stores/panes.ts（新增，~50 行）
state: {
  panes: [{ id: 'main', sessionId: null }],   // 栏序即布局序，main 常驻不可关
  activePaneId: 'main',
  nextId: 1,
}
getters: {
  // 兼容层：现有代码读 currentSessionId 的语义 = "活动栏的会话"
  activePane: (s) => s.panes.find(p => p.id === s.activePaneId),
}
actions: {
  openInPane(sessionId)   // 去重：已开则聚焦；上限受宽度约束
  closePane(id)           // main 不可关；关活动栏则焦点左移
  focusPane(id)
  bindPane(id, sessionId) // 栏内新建会话时回填 sid
}

// sessionStore.currentSessionId 改为 computed 别名：
//   get = panes.activePane.sessionId
//   set = 写回 activePane.sessionId
// → ConversationList 高亮、删除联动等现有逻辑零改动

// ChatArea.vue：computed(sid) → props.sid（watch 随 props 即可，滚动跟随逻辑不变）
// InputArea.vue：currentSessionId → props.sid（发送/上传/processing 全部按栏）
// App.vue：<ChatArea v-for="p in panes" :sid="p.sessionId" /> 外包 .chat-panes 容器
数据流不变：每栏发送仍走 useChatStream.send(sid) → openStream(sid) → 后端；流事件按 sid 写 store，各栏 computed 自动呈现——这正是"后台流"已验证的通路，多栏只是把消费端从 1 个变 N 个。

05模式与模型的作用域

维度v1（首版）二期（可选）

mock 中右栏展示栏级模式 chip（💬 问答）仅为二期形态预演；v1 两栏 chip 相同。

06边界与降级

窄窗口（<1200px）分栏容器折叠为"栏标签 + 单视图"（标签即栏），数据结构不变，仅呈现切换——保底可用性
终端视图 / 工作区面板不受影响：终端视图仍整区切换；WorkspacePanel 依旧挂在分栏容器右侧
空会话栏显示欢迎 Hero + 输入框（ChatArea 现有 welcome 分支按栏工作，Teleport 锚点为组件内 ref，天然隔离）
会话数不足新开栏支持"空白栏 + 新会话"：发送时按栏创建（InputArea 已有 createSession 分支，改为绑定到所在栏）
