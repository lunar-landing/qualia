任务中心列表重设计 · 四方案对比

现状痛点：状态弱（仅一个状态点）、无时序感（按创建时间平铺）、信息挤一行（时间列占宽大）、历史展开弱。 四个方案共用同一组示例数据（4 条任务：运行中 / 正常 / 暂停 / 最近失败），色值全部取自现有变量体系。
A

卡片精修 · meta 单链化

最稳
保留现卡片结构，信息重排：副行收成一条 meta 链「周期 · 上次 ✓ 时间 · 下次 时间」，时间列从右侧移除（省出约 100px 宽度给提示词）； 操作列 hover 浮现（平时只留开关 + 展开箭头）；最近失败的轮次摘要直接进 meta 链（红字），不用展开就能看到失败原因。
  • 改动最小：仅 DOM 重排 + CSS，交互语义不变
  • error 摘要前置：失败任务一眼看到原因
  • hover 才见操作钮，视觉更干净
  • 时序感依旧缺失（同现状按创建排序）

B

表格式密度布局

表头行 + 40px 紧凑行，列定位：状态并入「任务」列前缀点 + 「上次」列状态字。信息效率最高， 一屏可见任务数约为现卡片布局的 2 倍；点击行展开执行历史（表格行内展开）。
  • 密度最高：适合任务 10+ 的使用形态
  • 列对齐使「上次/下次」时间可纵向扫读
  • 代价：提示词长时截断更狠；移动端（<820px）需降级回卡片

C

时序面板 · 接下来运行队列

推荐
回答定时任务最本质的问题——「接下来会发生什么」。顶部「接下来」条按时间展示 24h 内的运行队列 （mono 大字最近一次 + 后续节点横排）；下方任务卡按下次运行时间升序，卡左缘 3px 状态带 （绿=正常 / 主题色=执行中 / 灰=暂停 / 红=最近失败）。启停开关常驻右侧，操作钮 hover 浮现。
  • 时序感最强：一眼看到「下次什么时候跑、跑什么」
  • 列表按 nextRunAt 排序 = 自然的优先级视图
  • 状态带在行内可纵向连成轨道，扫视性接近方案 C 旧稿
  • 代价：实现量最大（排序 + 队列条），但全部纯前端

D

主从双栏 · 列表 + 详情

左列窄列表（状态点 + 提示词 + 下次时间），右侧详情面板：提示词全文、周期、20 轮统计 （成功率 / 平均耗时）、执行历史完整表。信息架构最完整，把执行历史从「展开」升级为「常驻详情」。
  • 信息架构最完整：历史与统计不需要展开即可见
  • 宽屏利用率高；点击行切换详情即时
  • 代价：侧边栏场景偏重（现状单列已够用），任务少时右栏空旷
