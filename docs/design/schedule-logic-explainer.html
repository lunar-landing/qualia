定时任务逻辑 · 执行讲解

一条固定提示词 + cron 周期，到点由后台调度器复用对话管道执行
qualia-code 专属 零新依赖（Spring CronExpression） 单通道互斥 错过不补跑

01核心心智模型

没有独立调度框架：任务只是一条 JSON 定义，执行 = 到点自动发起一轮只读普通对话，完全复用 sendMessageFlux 管道。

定义态

ScheduleDef

prompt（固定提示词）+ cron（6 段）+ nextRunAt（下次触发时刻）+ runs（最近 20 条执行记录）。

schedules.json
调度态

20s 扫描 tick

daemon 单线程每 20 秒扫一遍：enabled 且 nextRunAt 已到 → 触发。触发即推算下一周期。

schedule-scanner
运行态（派生）

运行会话

每轮新建独立会话，只读模式发提示词；回复自然落进会话历史，qualia-core 零改动。

schedule-run × N
铁律：任务与会话解耦——会话不是任务的属性，而是每轮运行时派生的产物；执行记录回填消息 id，前端按 id 精确标注。

02调度循环（tick）

单次扫描只做到点判定，一轮对话的耗时与扫描解耦（执行交独立线程池）。

tick 每 20s→ list() 快照→ enabled?→ nextRunAt ≤ now?→ 不在 runningIds?→ startRun(scheduled)
1错过不补跑过期的 nextRunAt 只触发一次，进 startRun 即推算到下一周期——服务重启也一样（startupRecalibrate 重算未来）。tick() L234
2扫描与执行解耦扫描线程只负责触发，submit 到 cachedThreadPool 执行；单任务 30 分钟超时不阻塞扫描。startRun L279
3防重入runningIds 登记正在执行的任务 id，扫描与手动执行共用同一登记。runningIds

03互斥决策（点场景看路径）

全局单执行通道：与用户聊天共用 ChatService.isStreaming() 计数器（beginStream / endStream 记账）。

04执行一轮（execute）

一次运行 = 一个独立落地会话；完成后回读消息 id 写进执行记录，前端据此标注。

1新建运行会话标题取任务提示词截 30 字；sessionId 先写进执行记录（running 态），供前端跳转。createSession
2占用通道require 激活会话 → beginStream() 计数 +1，此后用户侧 isStreaming 为 true。L301-302
3只读发提示词sendMessageFlux(sessionId, prompt, null, CallOptions.readOnly())——只读模式不落工具写操作。readOnly()
4后台消费至终态CountDownLatch 等待完成/出错；30 分钟超时 → dispose + 记失败（防流挂死占通道）。RUN_TIMEOUT_MINUTES
5回读消息 id + 摘要末条 USER = 触发消息、末条 ASSISTANT = 回复；摘要取首行去 markdown 截 80 字。fillMessageRefs
6记账销账对称finally 里统一 endStream()（幂等兜底）+ persistRunResult 落盘；执行期间任务被删则丢弃记录。persistRunResult

05存储与容错

单文件 JSON 存储，风格对齐 MaterialService。

原子写盘

~/.qualia/code/schedules.json，先写 .tmp 再 move 替换，杜绝写一半损坏。

启动校准

nextRunAt 缺失或已过期 → 以 now 重算未来；重启后暂停期间错过的轮次不补跑。

脏 cron 兜底

cron 解析失败 → 顺延 1 小时而非禁用，避免日志风暴；下次编辑修正后自愈。

记录截断

每任务只留最近 20 条执行记录（MAX_RUNS），超出一律清除。

06前端触点（qualia-code-ui）

schedules.ts

有任务时 30s 轮询刷新；markByMsgId 把执行记录消息 id 做成标注索引。

ScheduleDialog

独立创建/改周期弹窗：每天/工作日/每周N 折算 cron，custom 直传后端校验。

SchedulesView

任务中心整栏视图（与资料库互斥）：立即执行/启停/改周期/删除 + 执行记录展开。

会话流标注

虚线气泡（触发消息）+ 尾部摘要行（回复），按消息 id 精确匹配；运行会话带时钟标识。

一句话：20s 扫描线程到点判定 → 忙则顺延、错过不补跑 → 新建会话只读跑一轮 → 消息 id 回写执行记录 → 前端按 id 精确标注，全程与用户聊天共用 isStreaming 单通道互斥。
