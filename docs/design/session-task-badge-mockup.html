任务运行会话标识 · 四方案对比

任务每轮运行新建独立会话（标题 = 提示词截 30 字），在会话列表里与普通会话无法区分。 数据链路：ScheduleRun.sessionId → schedules store 建 runSessionById: Record<sessionId, {def, run}> 索引， 行渲染时命中即套标识。以下四个方案共用同一组示例数据，色值全部取自现有变量体系。
A

行首图标位替换为时钟

会话行左端的 18px 图标槽，普通会话是气泡 fa-comment，任务运行会话替换为时钟 fa-clock（text-secondary）。零新增元素、不占额外宽度，图标语义即来源。
  • 最克制：行结构与行高完全不变，石墨风本色
  • 时钟 + 标题（提示词截断）已足够传达「这是任务跑的」
  • 代价：丢失「一轮对话」的气泡语义（可接受——标题本身就是提示词）

B

标题后缀 mono 描边徽章「任务」

标题右侧跟一枚 9.5px mono 描边 chip（border-color + text-muted，内含微型时钟）。气泡语义保留， 文字徽章让来源一眼可读；长标题省略号与 chip 互斥挤压（chip flex-shrink:0）。
  • 语义最直白：不用猜图标，中文「任务」直接标明
  • 与侧边栏「任务」入口文案呼应（entry: '任务'）
  • 代价：每行多一个元素，视觉密度略升

C

行首强调边线 + 时钟

行左缘 2.5px 内嵌竖线（box-shadow: inset 2.5px 0 0 var(--text-muted)）+ 图标位换时钟。 边线形成纵向轨道，多条任务会话在列表里连成视觉分组，扫视定位最快。
  • 扫视性最强：边缘线在任何缩放/密度下都可辨
  • 与项目「轮次标注用边线/描边」的既有语言一致
  • 代价：视觉噪音最高，普通会话多时整列都是线

D

标题下来源行（周期 · 上次运行）

双行布局：标题下加 10.5px 来源行「时钟 + 周期文本 + 上次运行时间」（mono）。信息最全——不点开就知道 这条会话属于哪个周期、最近何时跑的；行高 +14px。
  • 信息最全：来源、周期、时间三合一，与任务中心行同构
  • 时间用 mono 与右侧列时间字体呼应
  • 代价：列表密度下降；来源行文案长时截断
