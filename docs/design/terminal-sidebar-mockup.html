S1 换肤 · 成本最低

DOM 与交互零改动：终端视图开启时给 .sidebar 挂一个皮肤类，覆盖颜色变量 + 等宽字体 + 图标降级为文本符号。 rail 保持胶囊形，风险最小。

S2 全终端面板 · 最彻底

整栏重写为 CLI 语言：品牌带版本行、工作区一行 ❯ ~/path ▾、视图切换为文本 tab（ [sessions] files）、会话列表带 › 指示符、底部 :settings。 终端沉浸感最强，需替换侧边栏模板与交互样式。

S3 折中 · 结构保留

保留现有骨架（品牌行 / 工作区卡片 / 底部设置），只把控件语言终端化： rail 变分段文本开关、＋ 变键帽、会话行加 › 与左缘 accent 条、热力图绿色阶。 熟悉布局不变，改动中等。

W1 / W2 切换器

W1：品牌栏收进顶行，最近列表读作 $ cd path 命令历史，底部输入行支持直接输路径；最近视图一屏完成，最快。 W2：保留 recent / browse 双视图结构，仅浏览视图 ls 化 + 地址行 prompt 化，交互与现有一致，迁移最稳。可组合：W1 的 recent + W2 的 browse。

通用约束

仅终端视图开启时生效（皮肤类随 chatView 切换）；配色零新增（--t-* ）；日间为 GitHub Light 同源映射；能力集与信息架构不变。

P1 / P2 工作区面板

P1 换肤：头部与 Tab 结构不变（中文 Tab + 方括号激活态），变更列表升为 git status --short 短格式（M/A/D 状态字母 + 增删行数）。P2 全终端：头部 ▚ workspace 、Tab 英文文本化（changes · term · web ）、操作符 [+] [x]、底部汇总行；终端 Tab 仅换色，浏览器 Tab 加 ❯ 地址行。能力集与三 Tab 信息架构不变。

选型建议

求稳选 S1 + P1 + W2（纯皮肤，半天级）；求沉浸选 S2 + P2 + W1（模板重写）； 平衡选 S3 + W2，工作区面板按同向配套：S1/S3 配 P1，S2 配 P2。三区可独立选型。
