为什么降级为皮肤

上一稿替换了信息架构（tmux 顶栏 / 日志行 / 状态栏），要动 ChatArea、MessageItem、SidebarArea 的模板与状态管理，成本高、回归风险大、且无法与现有 UI 共存。换肤只动 CSS， 与现有界面随时互切，用户零学习成本。

三层正交架构

① 模式已有（body.light-theme + localStorage）；② 强调色在 theme-dark-mockup 中已定稿三方案；③ 皮肤新增 body.terminal-theme。三者叠加互不干扰， 持久化为一个偏好对象即可。

皮肤变量面（只动质感）

  • --font-ui → 等宽字体栈
  • --radius-* → 0~6px 归方
  • --bg-bubble-user → transparent 去气泡
  • --gap-msg → 18px 提密度
  • 前缀符号（❯ / :: / $ / ──）全用 ::before，不改 DOM

边界：不属于主题的部分

tmux 状态栏、顶栏会话 tabs、❯ 独立提示符列这类结构性元素不是皮肤能表达的， 若想要应作为独立功能迭代评估；一期主题功能明确不含它们。

落地改动清单

  • index.css：字体/间距收敛为变量 + body.terminal-theme 覆盖块
  • theme.ts：偏好扩展为 { mode, accent, skin }，apply 同步 class/attr 与 hljs link
  • SettingsDialog：新增「外观」Tab，三组分段选择器
  • i18n：zh-CN / en / ja 三语词条

分期建议

  • P0：主题基建 —— accent 三方案 + 设置 UI + 持久化（纯增量，低风险）
  • P1：终端皮肤 —— 变量覆盖 + 伪元素前缀 + 密度调整
  • P2：可选 CRT 配色（磷光绿/琥珀）、跟随系统模式
