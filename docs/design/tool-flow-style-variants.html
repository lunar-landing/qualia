执行步骤样式四款设计

统一行为协议（思考流式·完成折叠）· 四种视觉形态

四款总览

同一场景横向对比

四款共用同一行为底座：思考流式行（thinking 事件打字）→ 工具行（默认收起单行）→ 完成态折叠摘要。 差异只在视觉形态与信息密度。场景统一为「把部署经验整理进资料库」（2 轮 · 2 工具）。

01极简行内流
无边框纯文本行，状态点 + 动词 + 耗时。最轻量，几乎隐形。
密度低噪音最小改动最小
02时间线节点
左竖线 + 轮次节点，思考句挂在节点下，轮次结构一目了然。
轮次感强结构清晰推荐
03终端日志
深色内嵌面板 + 时间戳行，每事件一行日志。开发者审美。
密度最高IDE 气质深色固定
04徽章胶囊
圆角胶囊横排，思考句穿插其间。紧凑活泼，动作连读感。
横向省高轻快接近现状

04徽章胶囊

Capsule

动作收敛为圆角胶囊横排（图标 + 短名 + 状态点），思考句作为普通文本段落在胶囊之间穿插。横向排列省高度——同轮多个工具一行放下，是四款中纵向最紧凑的执行中形态。

实现改动面最小（chip 去壳）中（新增节点/竖线样式）大（新面板体系+深色固定）小（chip 改胶囊壳）
适合偏好安静克制结构叙事（推荐）极客/时序敏感紧凑轻快
推荐 02 时间线节点：唯一能显式表达「轮」的形态，与新 function calling 协议的轮次结构天然同构；折叠摘要条直接升级现有 think-toggle；详情组件全部复用。若偏好更轻的存在感，01 是最小改动方案；喜欢开发者审美选 03（可与 02 的轮次节点结合成「终端面板 + 左侧轮轨」混合形态）。选定后我出对应的落地改动清单。
