V1

并行窗格

PARALLEL PANES 务实演进风险最低

把「切项目」从销毁式跳转改成浏览器多标签：每个项目一个标签页常驻，后台流永远在线；支持分屏同览两个项目。tmux / IDE 编辑器标签的心智模型。

交互机制

  • 顶部标签 = 打开过的项目，常驻不销毁；标签上的绿点 = 该项目有流在跑
  • 分屏模式下两个窗格各自独立会话流，可同时观察两个项目的执行
  • 关闭标签只是「收起视图」，后台流仍由多实例承载，可随时重开

共存如何实现

直接对应后端 ChatServiceRegistry 多实例：一个标签绑定一个实例，互斥天然消失，是最贴合现有架构的映射。

优势 / 代价

  • 优势：心智零学习成本；与 IDE 用户习惯完全一致；改造路径最短
  • 代价：跨项目「总览」弱——不切标签就看不见全貌；标签多了需要溢出折叠
V2

项目驾驶舱

MISSION CONTROL 启动台心智总览最强

交互机制

  • 卡片 = 项目的实时投影：状态、进度条、迷你 sparkline 全部由 SSE 活动事件驱动
  • 点击卡片进入该项目（标签式或单视图均可叠加）；运行中的卡片持续呼吸
  • 驾驶舱本身可做首页，也可做成 Esc 随手唤起的覆盖层

共存如何实现

多实例照旧；新增一个 轻量聚合状态接口（每项目：最近会话 + 运行标志 + token 统计），卡片轮询或事件推送刷新。

优势 / 代价

  • 优势：一屏尽收所有项目的「现在」；把 token 统计等既有能力自然收编
  • 代价：深会话操作仍要进项目二层；卡片信息时效性依赖事件通道质量
V3

统一脉搏流

UNIFIED PULSE Feed 心智最反直觉也最诱人

干脆取消「进入某个项目」的主叙事：所有项目的活动汇成一条按时间倒序的脉搏流。项目降级为过滤器（色标 chips），你关注的不是「在哪个项目里」，而是「此刻什么在发生」。

交互机制

  • 流内卡片 = 会话级活动事件（消息完成 / 工具执行 / 文件落盘 / 等待确认）
  • 项目色标 + chips 过滤；点击卡片展开会话或直接接管（跳入该项目上下文）
  • 确认闸门类事件在流内置顶钉住——跨项目的人机协同排队一目了然

共存如何实现

后端把各实例的事件统一汇入全局活动总线（单条 SSE 下发，事件带 projectId）——前端只维护一条流，天然多项目。

优势 / 代价

  • 优势：单人多项目并行的终极形态；与既有 ReAct 交错时间线一脉相承
  • 代价：放弃「项目为容器」的确定性，依赖高质量的过滤与召回；事件协议需重设计
V4

会话星图

CONSTELLATION 空间记忆实验性

项目是恒星，会话是绕行卫星，运行中的会话拖着光点沿轨道公转。整个工作历史变成一张可缩放平移的星图——用空间位置承载记忆：项目放在哪，你就记得在哪。

交互机制

  • 卫星半径 = 会话消息量，轨道速度 = 活跃度；运行中的卫星变绿并加速
  • 悬停恒星展开卫星标签；点击卫星直接续聊（自动切换焦点项目）
  • 双星距离可表达「项目相关性」—— AI 主动把相关项目拉成星座（联动推荐）

共存如何实现

纯展示层创新：数据完全来自多实例状态聚合（V2 的聚合接口即可驱动），星图只是其中一种「投影」。

优势 / 代价

  • 优势：辨识度极高，情绪价值拉满；空间记忆对「项目很多」的用户真实有效
  • 代价：效率存疑，信息密度低；适合作为欢迎态 / 回顾态的可选皮肤而非主界面
V5

意图调度台

DISPATCHER 最激进一个入口统治一切

取消「先选项目再说话」：你只面对一个全局输入框，说出意图，调度 AI 判断该去哪个项目的哪个会话——自动路由、自动续聊、自动汇总。项目与会话的全部复杂性沉入后台任务抽屉。

交互机制

  • 全局对话 = 调度层：轻量 LLM 做意图 → (项目, 会话, 动作) 的路由决策
  • 路由决策透明可见（三行小字），可一键纠正——错误路由点一下即改投
  • 后台任务抽屉统一呈现所有项目的运行体；完成后以回执卡片回流到主对话

共存如何实现

多实例 + 全局活动总线（V3 的底座）之上，再加一层路由器：多项目共存从「用户管理」变成「AI 托管」。

优势 / 代价

  • 优势：交互面积趋近于零；对「多项目随手指派」的场景是降维打击
  • 代价：多一次路由 LLM 调用与延迟；路由错误伤信任；与现有「强项目上下文」（文件树、技能、Agent）冲突最大，只宜做增量入口
