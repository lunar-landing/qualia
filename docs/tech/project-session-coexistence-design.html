多项目的会话在侧边栏聚合可见、点击可继续；切换项目不打断其他项目正在运行的对话流
对标 Cursor / Claude Code 的「项目 × 会话」共存形态 · 存量数据零迁移

01现状与差距

会话存储已按项目物理隔离，改造集中在服务层与交互层。

维度现状与共存的差距
会话存储{workspace}/.qualia/sessions/{id}/session.json，天然按项目隔离无差距 零迁移
ChatService全局单例绑定焦点工作区，switchWorkspace 整体重建实例切项目即丢实例，旧项目会话列表消失
流式互斥ACTIVE_STREAMS 全局计数，有流时切换工作区返回 409 BUSY一次只能跑一个项目，切项目必须等流结束
项目列表WorkspaceHistory（recent）已有仅用于切换弹窗，未参与会话聚合
前端状态chat store 的 messagesBySession 按 sessionId 隔离无差距 天然支持多会话并行
结论：存储层已就绪，缺的只有两件事——聚合视图（跨项目会话可见）与运行并行（切换不互斥、后台流不中断）。

02总体方案 · 两阶段递进

P1 只动展示层即可用；P2 解除互斥，是「共存」的本质能力。

P1 聚合视图 改动最小

侧边栏会话列表按项目分组展示全部项目的会话；点击其他项目的会话自动切换焦点项目后加载。不解除流互斥。

WorkspaceHistory 遍历项目→ 只扫 session.json→ 双层分组渲染

P2 运行共存 核心能力

ChatService 单例改为按项目多实例，流计数实例化，解除切换互斥；切走后后台项目的流继续跑，事件照常入 store。

ChatServiceRegistry 多实例→ /switch 移除 409→ stream 带 workspace

03最终形态示意 · 侧边栏按项目分组

项目组（组头 = 项目名 + 路径，可折叠）→ 现有时间分组 → 会话行。流光晕与组头 spinner 复用现有 isProcessing。

ChatController · 聚合会话接口（P1）
// 项目来源 = WorkspaceHistory.list()，只读扫描，不触发 Agent / MCP 初始化
@GetMapping("/sessions/all")
public ResponseEntity<List<Map<String, Object>>> allSessions() {
    List<Map<String, Object>> groups = new ArrayList<>();
    for (WorkspaceRef ref : WorkspaceHistory.list()) {
        Path ws = Path.of(ref.path());
        if (!Files.isDirectory(ws.resolve(".qualia").resolve("sessions"))) continue;
        groups.add(Map.of(
            "workspacePath", ref.path(),
            "workspaceName", ref.name(),
            "sessions", ChatService.listSessions(ws)  // 静态只读：id / title / createdAt
        ));
    }
    return ResponseEntity.ok(groups);
}

public final class ChatServiceRegistry {
    private static final Map<Path, ChatService> SERVICES = new ConcurrentHashMap<>();
    private static final int MAX_INSTANCES = 8;

        evictIfNeeded();

@GetMapping("/stream")
public SseEmitter streamChat(@RequestParam String sessionId, @RequestParam String message,
                             @RequestParam(required = false) String model,
                             @RequestParam(required = false) String workspace) {
    return startStream(resolve(workspace), sessionId, message, model, null);
}

private ChatService resolve(String workspace) {
    Path ws = workspace != null ? Path.of(workspace) : WebApplication.getCurrentWorkspace();
    return ChatServiceRegistry.get(ws);  // 缺省 = 焦点项目，向后兼容
}

07边界与兼容

  • 存量数据零迁移：聚合靠目录扫描，旧会话自动归入对应项目组。
  • 资源上限：每项目一份 Agent + MCP 连接 + 模型缓存；注册表上限 8 实例，LRU 回收无流实例；全局配置与技能目录只读共享，无冲突。
  • 并发语义：同项目内多会话并行行为与现状一致，无回归；跨项目由「切项目必须等流」变为「互不打扰」。
  • 附件：回执仓库按 sessionId 全局存取，与项目无关。
  • token 统计：/stats/tokens 仍只算焦点项目，跨项目聚合统计列为后续可选项（P2.5）。
  • 桌面壳 / CLI：消费的接口语义未破坏，不感知此变更。
