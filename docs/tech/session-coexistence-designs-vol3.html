磁贴画布

TILE CANVAS 主画布分屏

聊天区本身变成磁贴布局：每个磁贴 = 一个项目的会话，独立输入框、独立流；布局随意组合（1+1、1+2、四宫格），分隔条可拖。多项目共存从「切换」升级为「同屏」。

要点

  • 磁贴 = (workspacePath, sessionId) 二元组的渲染实例；聊天区组件参数化复用
  • 布局方案（1+1 / 1+2 / 2+2）持久化到 localStorage；「⤢」一键把磁贴放大为唯一主磁贴
  • 与任何侧栏样式（Vol.2）正交叠加：点「分屏」按钮把某会话钉到画布

优劣

  • 优：并行任务「看得见」的终极形态；审一个项目的产出时另一个还能继续跑
  • 劣：小屏拥挤；多磁贴同时流式渲染有性能成本（需虚拟滚动兜底）

要点

  • 「从侧栏移除」= 从注册表摘除项目（不删数据）；孤星项目由此可治理

会话迁移看板

SESSION KANBAN 新能力：会话跨项目搬家需后端配合

列 = 项目，卡 = 会话。既然会话物理上就是 .qualia/sessions/ 里的一个目录，「把会话拖到另一个项目」就只是移动目录——看板把这个能力显性化：实验记录挪回主项目、临时项目的成果归档。

要点

  • 后端一个接口：POST /api/chat/sessions/move——搬运会话目录（session.json、custom title、summaries、files 附件）到目标项目
  • sessionId 为 UUID 全局唯一，迁移不改 ID；历史与附件整体跟随
  • 运行中的会话禁止迁移（沿用流互斥）；看板入口放「全部会话」聚合面板

优劣

  • 优：唯一带「写操作」的方案——整理历史、归档成果的真实生产力
  • 劣：拖拽在移动端不可用（补右键菜单）；误迁移需可撤销（移动前记录原路径）
D5

跨项目收件箱

INBOX 新能力：需要我的事

所有项目里「需要我处理的事」汇入一个收件箱：确认闸门（P2 已有的 approval-gate）、完成回执、失败告警。项目在后台各自跑，人只在被需要时出现——共存的最大收益是「放心地同时跑」。

要点

  • 数据源 = 各实例事件中的三类信号：pendingConfirmation / 完成 / 错误，汇入全局总线（与 V3 脉搏流同底座）
  • 入口常驻侧栏底部，未读数即徽章；收起时绝不打扰，展开时按项目过滤
  • 每条动作直达：批准 / 查看产物 / 带上下文续聊——收件箱是「接管点」不是「通知中心」

优劣

  • 优：把「多项目并行」的信任问题（怕出事没人管）变成产品能力；复用确认闸门机制
  • 劣：依赖事件总线与闸门状态上报的完备性；「已完成」类回执需要降噪策略
