02改造前后总览：会话双轨存储

问答默认不绑定工作区（自由问答），也可主动绑定；两种会话分轨存储，归属由目录位置表达。

改造前 现状

会话一律跟随工作区目录；启动可 null，null 时强制弹窗锁死整个应用，选完才能聊——不存在「不绑定工作区的问答」。

null 启动→ 强制弹窗→ 选工作区→ {ws}/.qualia/sessions

改造后 目标

新建会话默认自由问答（无需选工作区）；在项目下新建则绑定该项目。两条轨都存全局，工作区只留项目级配置。

默认：不绑定→ ~/.qualia/code/sessions/
主动绑定 workspace→ workspaces/{key}/sessions/
核心原则：归属由接口参数显式表达——创建与发消息接口带可选 workspace 参数：null = 自由问答域，非 null = 按工作区键控域。后端不猜测归属，目录位置即归属。

03目标目录布局：双轨

单会话目录内部布局完全不变（记录、摘要、附件同域聚合，删会话即删目录），变的只是 sessions 根的位置与轨数（自由域 + 键控域）。

04工作区键（wsKey）派生规则

路径 → 目录名的唯一映射，是键控存储的核心。编码保可读，哈希保唯一。

WorkspaceDataStore.wsKey()
/** 工作区键：归一化 → Windows 小写 → 非法字符编码 → sha256 前 8 位防碰撞 */
static String wsKey(Path workspace) {
    String normalized = workspace.toAbsolutePath().normalize().toString();
    if (IS_WINDOWS) {
        normalized = normalized.toLowerCase();  // 与 WorkspaceHistory 大小写不敏感去重对齐
    }
    String encoded = normalized.replaceAll("[^A-Za-z0-9-]", "-");
    String hash8   = sha256Hex(normalized).substring(0, 8);
    return encoded + "-" + hash8;
}
方案示例 / 问题结论
纯路径编码D:\Projects\qualia → D--Projects-qualia；但 D:\a b 与 D:\a-b 编码同串（碰撞），超长路径受 MAX_PATH 限制否决
纯哈希3fa1b2c4d5...；不可读，排查 / 手工清理困难否决
编码 + 短哈希d--projects-qualia-3fa1b2c4；人眼可识别项目，哈希保证唯一，超长时可安全截断编码段采用
meta.json 落盘原始路径：键反查、聚合视图展示名称、孤儿目录识别（path 已失效可提示清理）三用途。

05双轨路由：默认不绑定，主动可绑定

归属由接口参数显式表达，创建与发消息两处保持一致；后端按参数路由，不猜测归属。

域何时产生存储路径运行时
A 自由问答
默认		 新建会话不指定 workspace ~/.qualia/code/sessions/{id}/ 惰性创建自由 Agent：禁用全部文件类工具（无工作区根，读写无意义且有风险），保留全局技能 + 全局 AGENT.md
B 绑定工作区
可选		 新建会话显式指定 workspace workspaces/{wsKey}/sessions/{id}/ 按工作区实例化 Agent：文件工具 + 工作区技能/AGENT.md + 全局技能（对齐共存 P2 按项目多实例方向）
接口与路由workspace 参数可选，两处一致
// 创建会话：workspace 缺省 = 自由问答（域 A）
@PostMapping("/sessions")
public SessionInfo createSession(@RequestParam(required = false) String workspace) { ... }

// 发消息：workspace 与创建时保持一致，按域路由
@GetMapping("/stream")
public SseEmitter stream(..., @RequestParam(required = false) String workspace) { ... }

// 唯一路由入口：workspace == null → 域 A，非 null → 域 B 键控目录
static Path sessionDir(Path workspace, String sessionId) {
    return workspace == null
            ? WorkspaceDataStore.freeSessionsDir().resolve(sessionId)
            : WorkspaceDataStore.sessionsDir(workspace).resolve(sessionId);
}
  • 归属表达：目录位置即归属，session 数据不加工作区字段；getSessions 合并两域返回——自由会话打 free 标，绑定会话带 workspacePath（前端按组展示，自由问答组置顶）。
  • 启动语义简化：不再需要默认工作区解析与强制弹窗——null 焦点是正常稳态（自由问答不需要工作区）；currentWorkspace 退化为纯「文件浏览焦点」，按需选择。
  • 拦截重构：ChatController.noWorkspace() 不再是「拒绝聊天」，chat 接口无工作区时走自由域；文件树 / 工作区技能等焦点类接口维持「需先选工作区」。
  • 前端：删除 __qualiaNoWorkspace 强制流，picker 降级普通入口；新建会话默认自由，在项目组内新建则自动带上该项目 workspace。
  • CLI 保持：--cli 模式回退 user.dir 的现有行为不变（-w > user.dir）。

07存量数据迁移（惰性 · 幂等）

时机：sessionsDir() 首次访问时触发——打开即迁，未打开的工作区不动。与 claw migrateLegacyMemory 同款模式。

sessionsDir(ws) 首次调用→ 旧旧版 memory/ 并入→ 旧版 sessions/ 逐会话搬移→ 空目录清理→ 返回全局键控目录
WorkspaceDataStore.migrateIfLegacy()四步，逐项搬移不覆盖
/** 幂等迁移：工作区三代旧布局 → 全局键控目录（首次访问触发） */
static void migrateIfLegacy(Path workspace, Path targetSessions) {
    Path qualia = workspace.resolve(".qualia");

    // 1) 旧旧版 {ws}/.qualia/memory/* → 先并入 {ws}/.qualia/sessions/
    //    必须在产品层提前做：JsonMemory.migrateLegacyMemoryDir 依赖「父目录下有 memory/」，
    //    记忆目录迁到全局后 parent 变了，该逻辑会天然 no-op，失去迁移能力

    // 2) 旧版 {ws}/.qualia/sessions/{sid}/ 逐会话目录搬入 targetSessions/{sid}/
    //    目标已存在 = 已迁移过，跳过（中断重入安全，搬移不覆盖）

    // 3) 搬空删源目录；.qualia 只剩 AGENT.md / skills 则保留（项目级配置），全空则删

    // 4) 任一步 IOException → log.warn，本次直接使用 targetSessions 运行
    //    数据不销毁、留在原地，下次打开重试（与 claw 行为一致）
}
迁移完成后旧路径不再回读；不做双写——两份真值必然漂移。删除会话 / 附件清理语义不变（仍删单会话目录）。

10边界与权衡（明示接受的代价）

场景影响评估
项目移动 / 改名键失配产生孤儿会话目录非回归：现状 WorkspaceHistory 同样按路径失配（移动即视作新工作区）；后续可加「meta.json.path 失效 → 提示重新关联」维护项
subst / symlink不同归一化路径 = 不同键，会话分叉与现状一致，接受
多设备同步会话不随项目目录走非回归：现状实际使用亦如此（无人把 .qualia 提交进 git）
Windows 大小写键派生统一小写与 WorkspaceHistory 去重规则对齐，不会因打开时大小写不同产生双目录
迁移失败权限 / 文件占用导致搬移中断warn 后用新目录继续，数据留原地下次重试；逐项搬移保证中断重入安全
