01目标形态：绑定是会话的可选属性

废除「先选工作区才能用」的前置门槛。新会话一律落在默认工作区（会话域内派生沙箱），用户显式绑定项目文件夹后该会话的 Agent 根目录切到项目根；绑定/解绑只读写 binding.json，零迁移。

一句话：启动即可聊；绑定 = 为当前会话写 binding.json（仅绑定接口可写，信任边界不变）；解绑 = 删字段回默认态。改造后三区各管一件事，互不交叉：侧栏管全局历史 · chip 管当前绑定 · 面板管当前会话的工作现场。

◇ 默认工作区（派生沙箱）

会话创建即用的形态。Agent 根目录指向会话域内 sessions/{sid}/workspace/（发首条消息时惰性创建，空会话不落盘）；全局配置/技能/MCP 照常加载，文件操作隔离在会话沙箱内，不触碰任何项目目录。

新建会话→ ◇ 默认工作区→ 直接提问

📁 绑定工作区（项目根）

用户显式动作后写入 binding.json。Agent 根目录切换到项目根，获得项目文件上下文；项目目录零会话数据写入。解绑随时回默认态，会话数据不丢。

◇ 默认工作区→ 绑定文件夹…→ 📁 项目根
~/.qualia/code/ 存储布局（已实施，不变） 会话统一全局桶 · 绑定差异只在 binding.json

ChatService.java 根目录解析：绑定优先，缺省派生 
/** Agent 根目录：绑定 → 项目根；未绑定 → 会话域派生工作区（惰性创建） */
private Path resolveAgentRoot(String sessionId) {
    Path bound = WorkspaceDataStore.readBinding(sessionId);  // binding.json 唯一权威
    if (bound != null) {
        return bound;                                        // 项目根：按项目加载上下文
    }
    return WorkspaceDataStore.sessionDir(sessionId)
            .resolve("workspace");                           // 派生沙箱：首条消息时惰性创建
}

/** 会话激活 / 绑定变更的统一入口：root 变化才重建，同 root 零开销 */
public static synchronized void require(String sessionId) {
    Path root = resolveAgentRoot(sessionId);
    if (instance == null || !instance.root.equals(root)) {
        switchWorkspace(root);          // 复用既有重建：reloadConfig + new ChatService
    }
    instance.activeSessionId = sessionId;
}
ChatController.java 绑定 / 解绑：信任边界唯一入口 
/** 绑定/解绑当前会话的工作区（body: {"workspace": "路径"}；缺省或空 = 解绑） */
@PostMapping("/sessions/{sessionId}/bind")
public ResponseEntity<Map<String, Object>> bind(@PathVariable String sessionId,
        @RequestBody(required = false) Map<String, String> body) {
    if (ChatService.isStreaming(sessionId)) {
        return ResponseEntity.status(409).body(Map.of("error", "流式对话进行中，暂不能变更绑定"));
    }
    String ws = body == null ? null : body.get("workspace");
    if (ws != null && !Files.isDirectory(Path.of(ws))) {
        return ResponseEntity.badRequest().body(Map.of("error", "目录不存在"));
    }
    WorkspaceDataStore.writeBinding(sessionId, ws == null ? null : Path.of(ws)); // null = 删 binding.json
    ChatService.require(sessionId);   // root 变化时重建实例 + 镜像 currentWorkspace
    return ResponseEntity.ok(Map.of("success", true, "session", ChatService.getInstance().getSession(sessionId)));
}

05关键数据流：三条主链路

前端步（蓝）与后端步（灰）按序执行；F = 前端，B = 后端。

链路 1 · 启动直达（未绑定）

  1. F1打开应用：不再检查全局工作区，直接进主界面；无历史 → Hero 欢迎页 + 引导条 + chip「◇ 默认工作区」
  2. F2GET /api/chat/sessions 拉全量列表（此时也可并行）
  3. B1getSessions 全量返回，逐条附 workspace 字段；无启动前置条件
  4. F3用户直接提问 → POST /stream
  5. B2ChatService.require(sid) → resolveAgentRoot = sessions/{sid}/workspace/（首条消息时惰性创建）→ Agent 在沙箱内干活

链路 2 · 换绑 / 解绑（chip 菜单）

  1. F1chip 下拉选「最近项目」或「浏览文件夹…」（后者弹降级版 WorkspaceSwitcher）
  2. F2POST /api/chat/sessions/{sid}/bind（流式中按钮已禁用，后端 409 兜底）
  3. B1校验目录存在 → writeBinding → require(sid)：root 变化 → switchWorkspace 重建（MCP/配置重载）→ 镜像 currentWorkspace
  4. F3响应后一次性刷新三区：chip 换态 → 面板文件树/变更重载 → 会话列表重新分组（会话从◇组移入项目组）

链路 3 · 项目组悬停 ＋（进项目干活，承接旧「切换工作区」意图）

  1. F1项目组行悬停 → 点 ＋
  2. F2POST /api/chat/sessions 新会话（派生态）→ 紧接 POST .../bind {"workspace": 该项目}
  3. B1两步落盘：session.json 建立 → binding.json 写入 → require 切 root（若当前实例已在该项目 root 则零重建）
  4. F3切到新会话：chip 已是 📁 项目名，面板展示项目树，直接开聊

07边界与风险

全部为已知可接受项，无阻断风险。

  • Agent 重建开销：跨 root 切换会话触发 MCP / 配置重载（秒级）；同 root 复用零开销；流式互斥已有（ACTIVE_STREAMS），重建期间 UI 由既有加载态覆盖。
  • getInstance 隐患顺带修复：现状 getInstance(Path) 实例创建后忽略路径差异；本批统一收敛到 require(sid) 单入口，消除「Controller 持旧实例读旧工作区」类问题。
  • 旧端点兼容：/api/workspace/switch 保留但前端不再调用；其「切全局」语义与 D1 冲突，后续版本可评估移除。
  • 派生沙箱不进最近列表：防污染工作区历史视图；会话删除随域目录整体清理，外部项目不受影响。
  • 老用户感知：升级后侧栏从「单项目列表」变「全量分组」，属预期产品行为变化，归属数据已由存量迁移补写。
  • 空会话不落盘：仅创建未发消息的会话不建派生目录，列表继续过滤空会话。
  • 信任边界不变：binding.json 仅绑定接口可写，消息 / 模型输出不可触达。
